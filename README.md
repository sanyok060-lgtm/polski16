# Polski 16 — сборка PWA + Android APK

Готовый пакет для GitHub: один и тот же тренажёр работает и как сайт
(PWA — можно поставить на экран телефона как приложение), и как APK-файл,
который сама GitHub Actions собирает в фоне при каждой загрузке.
Содержимое самого тренажёра (`docs/index.html`) не менялось — добавлены
только 8 строк в `<head>` для подключения PWA.

## Что внутри

- **`docs/`** — сам тренажёр + иконки + манифест + service worker для
  офлайна. GitHub Pages будет отдавать сайт именно из этой папки.
- **`android-signing/polski16.jks`** — постоянный ключ подписи приложения.
  Сгенерирован один раз и используется для всех сборок (пароли — ниже).
- **`.github/workflows/android.yml`** — сборка APK в GitHub Actions.
- **`package.json` / `package-lock.json` / `capacitor.config.json`** —
  конфигурация Capacitor. Сама Android-обёртка (папка `android/`) в архиве
  отсутствует и не нужна — CI создаёт её заново при каждой сборке командой
  `npx cap add android`, поэтому репозиторий компактный и его удобно
  загружать вручную через браузер.

## 1. Как загрузить репозиторий на GitHub через браузер

1. На github.com нажмите **+** → **New repository**. Название — например
   `polski16-app`. Остальное не трогайте → **Create repository**.
2. На странице пустого репозитория нажмите **uploading an existing file**.
3. Разархивируйте `polski16-app.zip` на компьютере и перетащите в окно
   браузера **все** файлы и папки разом: `docs`, `android-signing`,
   `.github`, `package.json`, `package-lock.json`, `capacitor.config.json`,
   `.gitignore`, `README.md`. GitHub сохраняет вложенность папок при
   перетаскивании.

   ⚠️ Папка `.github` начинается с точки и в Finder/Проводнике может быть
   скрыта. Если она не показывается — включите показ скрытых файлов
   (Finder: `⌘+Shift+.`; Проводник Windows: вкладка «Вид» → «Скрытые
   элементы»). Либо загрузите файл отдельно: **Add file → Create new
   file** и впишите в поле имени сразу путь целиком —
   `.github/workflows/android.yml` — GitHub сам создаст нужные папки.
4. Внизу страницы нажмите **Commit changes**.

## 2. Как скачать APK во вкладке Actions

1. Откройте репозиторий → вкладка **Actions**.
2. Если сборка не запустилась сама (для самого первого workflow иногда
   нужно подтверждение) — слева откройте **Build Android APK** → справа
   кнопка **Run workflow** → ещё раз **Run workflow** для подтверждения.
3. Дождитесь зелёной галочки — сборка занимает обычно 3–5 минут.
4. Откройте завершившийся запуск → внизу страницы раздел **Artifacts** →
   скачайте `polski16-apk` (это zip-архив, внутри — `app-release.apk`).
5. На телефоне откройте скачанный `app-release.apk`. Android спросит
   разрешение на установку «из неизвестных источников» — это нормально
   для APK не из Google Play, разрешите установку.

При каждом следующем обновлении `docs/index.html` в репозитории просто
повторяйте этот раздел — новый APK подписан тем же ключом, что и
предыдущий, поэтому Android установит его поверх старого, а прогресс в
приложении не потеряется.

## 3. Как включить GitHub Pages (сайт/PWA)

1. Репозиторий → **Settings** → **Pages** (в левом меню).
2. Source: **Deploy from a branch**. Branch: **main**, папка: **/docs** →
   **Save**.
3. Через 1–2 минуты сайт откроется по адресу
   `https://<ваш-логин>.github.io/<название-репозитория>/`.

## 4. Как добавить сайт на экран «Домой» на iPhone

1. Откройте адрес сайта в **Safari** (обязательно в Safari — iOS
   разрешает устанавливать PWA только через него, не через Chrome).
2. Нажмите кнопку «Поделиться» (квадрат со стрелкой вверх).
3. Выберите **«На экран Домой»** → **«Добавить»**.

Иконка откроется в полноэкранном режиме без адресной строки браузера и
будет работать офлайн — после первого открытия сайт кешируется на
устройстве (см. про service worker ниже).

## Пароли и ключ подписи

| Параметр | Значение |
|---|---|
| Файл ключа | `android-signing/polski16.jks` |
| Alias (keyAlias) | `polski16` |
| Store password | `QT3hAuzONEen9uWCy88R` |
| Key password | `QT3hAuzONEen9uWCy88R` (совпадает со store password) |
| Срок действия | до 6 февраля 2054 |
| Отпечаток SHA-256 | `3D:3B:39:CA:D0:E8:74:33:76:8D:67:51:98:F9:DA:A1:DD:B6:AE:76:24:E6:5B:3B:06:AF:CC:B9:7E:D3:83:31` |

Эти же пароли уже вписаны напрямую в `.github/workflows/android.yml` —
workflow сам добавляет блок `signingConfigs` в `android/app/build.gradle`
после того, как создаст папку `android/`, и подписывает им **и** debug,
и release сборки. Ничего дополнительно вводить не нужно, APK соберётся и
будет подписан автоматически.

**Важно:** это единственная копия ключа. Если её потерять — все
следующие обновления APK будут для Android «другим приложением», и
пользователям придётся удалить старую версию (с потерей локального
прогресса) перед установкой новой. Стоит один раз скачать
`android-signing/polski16.jks` и пароли из этого README в отдельное
безопасное место (например, менеджер паролей) — на случай, если
репозиторий когда-нибудь удалится.

**О приватности репозитория:** пароли от ключа лежат прямо в репозитории
открытым текстом (так вы и просили — просто и без лишней настройки). Для
личного офлайн-приложения, которое не публикуется в Google Play, это
практический риск, а не критичный: подделать обновление сможет только
тот, у кого есть доступ к самому репозиторию. Но если репозиторий
**публичный**, пароли и ключ увидит любой желающий. Если захотите
закрыть эту лазейку позже — можно перенести пароли в GitHub Actions
Secrets (Settings → Secrets and variables → Actions) и заменить в
`android.yml` вписанные строки на `${{ secrets.KEYSTORE_PASSWORD }}`;
файл ключа при этом всё равно останется в репозитории, но пароль к нему
— нет. Менять это прямо сейчас необязательно.

## Технические примечания

- **Почему `webDir` в `capacitor.config.json` указывает на `docs`, а не
  на корень репозитория.** Capacitor копирует **всё содержимое** папки
  `webDir` внутрь APK как есть. Если бы это был корень репозитория,
  внутрь приложения попали бы и `android-signing/polski16.jks`, и этот
  README с паролями — то есть ключ подписи и пароль к нему разъезжались
  бы вместе с каждой установкой APK. Поэтому под сайт выделена
  отдельная папка `docs/` — в ней ровно то, что должно быть публичным
  (тренажёр, манифест, иконки, service worker), `index.html` лежит прямо
  в её корне. Заодно эта же папка `/docs` — стандартный, поддерживаемый
  GitHub Pages источник (настраивается в разделе 3 выше).
- **Почему папки `android/` и `node_modules/` нет в архиве.** Обе
  создаются автоматически при сборке (`npm ci` ставит зависимости,
  `npx cap add android` генерирует нативный проект) — так репозиторий
  остаётся маленьким и его удобно загрузить вручную через браузер, без
  git и командной строки.
- **Формат `.jks`.** Современный `keytool` по умолчанию создаёт ключи в
  формате PKCS12, а не в старом JKS — файл называется `polski16.jks` по
  вашей просьбе, но по факту внутри PKCS12. Для Android/Gradle это не
  имеет значения, оба формата поддерживаются одинаково.
- **Офлайн-кеш (service worker).** `docs/sw.js` кеширует `index.html`,
  манифест и иконки при первом открытии сайта. Если потом обновите
  `docs/index.html` и хотите, чтобы у пользователей подтянулась новая
  версия — поднимите номер в строке `const CACHE_VERSION = 'polski16-v1'`
  (например, на `'polski16-v2'`) в `docs/sw.js`, иначе часть
  пользователей может какое-то время видеть старую закешированную
  версию.
- **Что не проверялось локально.** Сама сборка Gradle (`assembleRelease`)
  требует Android SDK и доступ к репозиторию Google Maven — этого нет в
  среде, где готовился этот архив, поэтому финальную сборку выполнит
  только GitHub Actions при первом запуске. Структура `capacitor.config.json`,
  подстановка `signingConfig` в `build.gradle` и то, что `cap sync` не
  копирует лишнее в APK — всё это проверено вручную перед упаковкой.
